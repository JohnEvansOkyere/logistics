# Delivery plan — bounded agent work and production gates

Each phase should be split into small vertical features with their own acceptance checks. Work on one coherent deliverable per agent session; document demo/test evidence next to the [master checklist](../CHECKLIST.md). The numbered phases show dependencies, **not a rule that every question in phase 0 must be answered before development starts**. Send [questions.md](../questions.md) while beginning phase 1 and other independent work; use documented, reversible assumptions for early prototypes. Confirm a decision before shipping the behavior that depends on it. No phase is complete because code compiles alone.

The SQLite adapter has been retired (2026-09-29); Supabase PostgreSQL is the only database. A local Supabase/PostgreSQL harness now verifies the initial private-schema migration and transaction-scoped synthetic RLS probes for company membership and provisional staff workflow scopes. Define application schema only in reviewed `supabase/migrations/` SQL and independently test the approved business grants, RLS, and company isolation. These probes do not establish the product's complete role or visibility rules.

## Vertical-feature template for a coding agent

1. **Goal and references:** requirement ID (Pxx), relevant workflow, decision IDs, affected user roles and one concrete scenario.
2. **Implementation:** DB migration/grant → domain rule/transaction/API → UI or worker adapter → audit/permission controls; add no unrelated features.
3. **Acceptance:** positive and denied paths, failures/retries, synthetic fixture, exact verification command; demo to operator for ambiguous flow.
4. **Close-out:** review diff, run checks, document evidence and decisions; tick only finished checklist boxes. If blocked by external provider or client input, retain a usable manual flow and mark the blocked item as open.

## Definition of production-ready

All P01–P14 (including email/SMS under P11) are implemented to signed-off acceptance or explicitly removed by a **new recorded scope decision**; no unresolved high-priority questions for released behavior; CI/staging/UAT and the security/restore/release gates in [CHECKLIST.md](../CHECKLIST.md) pass. Phase 7/WhatsApp is expressly outside this initial launch gate. Third-party coverage is measured and reported by provider; a manual workflow is valid where an integration is unavailable and the client accepts it.
